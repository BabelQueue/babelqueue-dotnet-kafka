# Changelog

All notable changes to `BabelQueue.Kafka` are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and
this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
The envelope wire format is versioned separately by `meta.schema_version`
(currently **1**) — see the contract at [babelqueue.com](https://babelqueue.com).

## [Unreleased]

### Changed
- `KafkaConsumer` now dead-letters an undecodable / poison body **wrapped**, matching the Go reference (§6.5), instead of forwarding the raw bytes. A body that is not valid UTF-8 or that the Go reference's typed `babelqueue.Decode` rejects **Behaviour change - the poison trigger set is now exactly Go's:** malformed JSON (leading zeros, `NaN`, trailing tokens, a BOM, a second object, empty body) or a non-object value; `data` / `meta` / `dead_letter` not an object; `job`, `trace_id`, `meta.id|queue|lang` or `dead_letter.reason|error|exception|original_queue|lang` not a string; `meta.schema_version`, `meta.created_at`, `attempts` or `dead_letter.failed_at|attempts` not an integer that fits int64 (so `"2026"`, a fraction, `1e2` or an out-of-range value is poison); a number in `data` that is not a finite double (`1e400`). Duplicate keys are each type-checked and member names are matched exactly as spelled (case-sensitive, as the contract schema and the core decoder read them; `JOB` or `Meta` is an unknown member). A bare JSON `null` body is not poison (empty envelope, unknown-URN path) and a non-string `urn` alias is ignored. A well-typed but non-conformant envelope (missing `data`, blank `trace_id`, body `schema_version` other than 1) is **no longer dead-lettered** by `EnvelopeCodec.Accepts`: like Go, which never calls `Accepts` on consume, it is routed by its URN to the handler (an empty URN takes the unknown-URN path). Previously only a top-level subset was checked and `Accepts` failures were parked. A poison record is written to `<topic>.dlq` as one compact JSON object: a body that is a single JSON object keeps its keys and values (numbers verbatim), anything else becomes `{"raw":"<body>"}` (invalid UTF-8 as U+FFFD), and a `dead_letter` block with `reason: "poison"` (`error`, `exception`, `failed_at`, `original_queue`, `attempts`, `lang`) is set, replacing any existing one. The record key is preserved byte-for-byte (null stays null, empty stays empty); the offset is committed only after the DLQ write, and a failed write still seeks back. The `bq-schema-version` gate (§6.7) is **unchanged** and still forwards the raw record. No change to the wire envelope or the `dead_letter` shape (`schema_version` stays 1).
- Poison DLQ records: `KafkaHeaders.Project` no longer projects `bq-schema-version: 0` when the body has no `meta.schema_version` (a later §6.7 gate would have rejected the DLQ record). Remaining, intentional differences from the Go reference for a poison record: `dead_letter.attempts` is the `bq-attempts` header (Go writes 0) and `original_queue` is the `bq-original-topic` header when present (Go writes the consumed topic); the DLQ record also carries `bq-original-topic` plus the `bq-*` headers projected from the body (Go adds no headers); and a float literal such as `1.0` / `1e2` is re-formatted where the body is re-encoded. The wire envelope and the `dead_letter` shape are unchanged.
- **Any decode failure is poison; the partition is never left to wedge.** The "exactly Go's" trigger set above is corrected in two respects. (1) Whatever `EnvelopeCodec.Decode` throws on a body the shape scanner accepted is now dead-lettered as poison (it previously escaped `PollAsync`, so the offset was never committed and the partition was redelivered forever); a body with a lone UTF-16 surrogate escape (`"\ud800"`), which Go accepts by substituting U+FFFD, is poison here and its DLQ body is carried verbatim under `raw`. (2) Member names are matched case-sensitively, exactly as the core decoder reads them (no `encoding/json`-style folding, no `OrdinalIgnoreCase`); the Go reference's case-insensitive read contradicts the contract schema and is tightened separately. Invalid UTF-8 is also poison here, whereas Go replaces it with U+FFFD and accepts it. The wire envelope and the `dead_letter` shape are unchanged.

- **A body nested deeper than the core codec can decode is poison, never an empty envelope.** `EnvelopeCodec.Decode` (System.Text.Json, default MaxDepth 64) silently returns an EMPTY envelope for a body nested more than 63 levels, where Go decodes up to 10000. With `Accepts` gone from the consume path that empty envelope would reach the handler with its content lost, or - with `UnknownUrn=Fail` and no `bq-job` header - wedge the partition. The consumer now checks the core's own depth limit first and dead-letters such a body as poison (reason `poison`), parked verbatim with its `job`/`data`/`meta` keys kept; it is always committed. (Intentional difference from Go, which would handle it.) The poison-body builder and the writer now allow 10000 levels (the shape scan's own limit was already 10000), so a deep poison body no longer loses its keys, and the scan's finite-number walk over `data` is iterative (a recursive walk overflowed the stack near 10000 levels). The `bq-*` headers projected onto such a DLQ record are best effort (empty), as the core cannot decode the body. The wire envelope and the `dead_letter` shape are unchanged.

### Added
- `KafkaRedriveTransport` now implements the core's optional `Redrive.IRewinder`. Whenever an exception ends a DLQ redrive run early — a failed restore write back to the DLQ, a failed redrive write (whose restore succeeded or not), a failed commit, or a throwing `Select` callback — `Redrive.RedriveAsync` calls `RewindAsync`, which seeks **every partition that still has a handed-out, uncommitted record** back to its lowest such offset (the same `Seek` path `KafkaConsumer` uses), so the whole rest of the drained batch is redelivered on the next poll, not just the failed record's partition. Kafka commits are cumulative, so without this a later commit by the same consumer could move the group past an unsettled DLQ record and lose it. Records already committed (including a restored record) are never sought back to, so nothing is duplicated. If the seek also fails, both errors are reported together. **Requires the `BabelQueue.Core` release that ships `Redrive.IRewinder` (1.10.0)**; the package reference is raised accordingly. No change to the wire envelope, `dead_letter` shape or header names.

## [1.1.0] - 2026-10-11

### Added
- `KafkaRedriveTransport`: a `Redrive.ITransport` over Kafka (consumer on the `<topic>.dlq` topic + producer) for the core's DLQ redrive (ADR-0026). It also implements the core's optional `Redrive.IKeyedRepublisher`, so a redrive carries the DLQ record's key **byte-for-byte** (null stays null, empty stays empty, none synthesised — contract §6.5) on both the redrive write to the work topic and every restore write back to the DLQ (dry run, unselected, undecodable body, failed redrive write). A restore re-writes the DLQ record **verbatim** (original value bytes — a null value stays null — original headers such as `traceparent` and `bq-schema-version`, and key) with a fresh timestamp; a record whose value is not valid UTF-8 is popped with an empty body (strict decode), so it is restored byte-for-byte and its offset is committed only after that write succeeded. A redrive to the work topic re-projects the `bq-` headers from the body published and keeps the envelope's `created_at` as the record timestamp. `PopAsync` skips partition-EOF markers and keeps polling until the poll timeout is exhausted instead of treating EOF as "DLQ empty". The `bq-replay-bypass` header is not propagated by this transport. **Requires `BabelQueue.Core` 1.9.0**, which ships `Redrive.IKeyedRepublisher`; the package reference is now `1.9.0`. No change to the wire envelope, `dead_letter` shape or header names.

### Fixed
- `KafkaConsumer` no longer lets a throwing `OnError` callback bypass settlement on the non-conformant-envelope and handler-failure paths. Previously `OnError` ran *before* the raw DLQ write + commit (non-conformant envelope) and before the retry republish / DLQ write + commit (handler failure); a throwing callback skipped the settlement and the record was redelivered forever. Both paths now settle first and report afterwards through the isolated `SafeReport` (as the schema-version gate and invalid-UTF-8 paths already did), and the unknown-URN `Fail` path reports through it too, so the intended `UnknownUrnException` still surfaces. If settlement itself fails (DLQ / retry write or the commit), the record is sought back first and `OnError` is then still reported (isolated) with the original error. No public API change; wire envelope, `dead_letter` shape and header names are unchanged.

## [1.0.3] - 2026-10-11

### Fixed
- `KafkaConsumer` now preserves the original record key when it republishes a record: the retry-tier write, the unknown-URN release and the annotated envelope `<topic>.dlq` write previously produced a `null` key. A null key stays null, an empty key stays empty and no key is synthesised; the raw/poison DLQ already kept it. Partition equality is not guaranteed. No public API change; wire envelope, `dead_letter` shape and header names are unchanged (`schema_version` stays 1). Patch-level behaviour fix.
- `KafkaConsumer` now decodes the record body as **strict** UTF-8. Previously `Encoding.UTF8.GetString` silently replaced invalid bytes with U+FFFD, so a structurally valid envelope with a corrupted string inside `data` was accepted and handed to a handler with altered content. A body that is not valid UTF-8 is now treated as poison, matching the Java/Go/Node transports: the original bytes (and key/headers) are forwarded raw to `<topic>.dlq`, the offset is committed, and only then does `OnError` receive a `BabelQueueException` (isolated: a throwing callback cannot bypass the DLQ write or commit). If the DLQ write fails the record is not committed and the consumer seeks back (unchanged settlement behaviour); with no DLQ topic configured the record is just committed. The `bq-schema-version` header keeps its lenient decode: invalid bytes yield U+FFFD, which never equals `"1"`, so such a record is already rejected by the schema-version gate. No public API change; wire envelope, `dead_letter` shape and header names are unchanged.

## [1.0.2] - 2026-10-11

### Fixed
- `KafkaConsumer` now preserves the source record's key on the raw forward to `<topic>.dlq` (poison body / schema-version gate), matching the Java and Node transports. Previously the key was dropped, so DLQ partition assignment and key-based triage diverged from the source topic. The annotated `dead_letter` envelope and retry-tier republish are unchanged (parity with Java/Node). No public API change; wire envelope and header names are unchanged.
- `KafkaConsumer` no longer loses a record when its settlement throws. Previously a failing poison-body DLQ write, retry-tier / DLQ republish after a handler failure, or unknown-URN DeadLetter / Release / Fail settlement threw out of `PollAsync` after `Consume` had already advanced the in-memory position; a restarted loop then received the *next* record and committing it (Kafka offsets are cumulative) skipped the unsettled one. `PollAsync` now `Seek`s back to the record's offset on any settlement failure (including cancellation) before rethrowing, without committing it, so the record is redelivered. If the seek itself fails a `BabelQueueException` wrapping both errors is thrown. Supersedes the 1.0.1 note that the other DLQ paths are unchanged. Behaviour note: with neither retry tiers nor a DLQ topic configured, a handler failure raises `BabelQueueException`; that record is now redelivered on every poll (the partition stalls on it) instead of being skipped after a restart, so configure retry topics or a DLQ. Requires `EnableAutoCommit = false` as documented. No public API change.

## [1.0.1] - 2026-10-10

### Fixed
- `KafkaConsumer` now checks the `bq-schema-version` header (UTF-8) **before** decoding the record (§6.7). A value other than exactly `"1"` (ordinal, untrimmed) is forwarded raw to `<topic>.dlq` and committed without decoding, the same path as an undecodable record (a no-op forward when no DLQ topic is configured, so the record is just committed). A header with a null value counts as absent. Absent or blank (empty / ASCII whitespace) falls through to the normal decode. No public API change.
- The schema-version gate no longer loses a record when the DLQ write fails: `KafkaConsumer` now `Seek`s back to the failed record's offset (so a later record's cumulative commit cannot skip it), does not commit it, reports via `OnError` and backs off for one `PollTimeout`; the record never reaches a handler. `OnError` is invoked **after** the commit / seek-back and isolated, so a throwing callback cannot bypass the protection. If the seek itself fails a `BabelQueueException` wrapping both errors is thrown. Other DLQ paths (poison body, exhausted retries, unknown URN) are unchanged. No public API change.

## [1.0.0] - 2026-06-13

### Added
- Initial release. An Apache Kafka transport on `BabelQueue.Core` + `Confluent.Kafka`,
  implementing §6 of the broker-bindings contract. Kafka has no native ack/delay/DLQ/delivery-
  counter, so the binding absorbs all four: `KafkaPublisher` (value = canonical envelope,
  record timestamp = `meta.created_at`, the `bq-` header projection — `bq-job` routes; a delay
  routes to a `<topic>.retry.<n>` tier or raises without one) and `KafkaConsumer`
  (**process-then-commit** manual-commit consume; a throwing handler republishes to the next
  retry tier with **`bq-attempts + 1`** then commits; terminal failures go to `<topic>.dlq` with
  the additive `dead_letter` block; the `bq-attempts` header is the authoritative counter with
  the body as fallback; `fail`/`delete`/`release`/`dead_letter` unknown-URN strategies; poison
  records forwarded raw to the DLQ). `RetryTopics` configures the tiered retry/delay topology.
  .NET 8, xUnit, analyzers-as-errors, ≥90% line coverage; the `IProducer`/`IConsumer` interfaces
  are mocked with Moq (no Kafka, no network). The envelope is unchanged (`schema_version: 1`);
  Apache Kafka is purely additive.
